# Diagnosis of CPython Cross-Compilation Errors on NanVix

## Error 1: pyconfig.h has #undef SIZEOF_VOID_P

**Cause:** CRLF (Windows) line endings in `nanvix-port/config.site`.
**Analysis:**
- The `config.site` file is mounted from Windows into the Docker container, preserving `\r\n` line endings.
- When `configure` sources this file, variables like `ac_cv_sizeof_void_p` acquire a trailing carriage return (e.g., `4\r`).
- `configure` writes `#define SIZEOF_VOID_P 4\r` into `confdefs.h`.
- `config.status` (generated by configure) tries to substitute values into `pyconfig.h.in`.
- The regular expressions or logic in `config.status` fail to match or correctly substitute the value due to the unexpected `\r`, leaving `#undef SIZEOF_VOID_P` in `pyconfig.h`.

**Fix:** Strip CRLF from `config.site` before passing it to `configure`.

## Error 2: fdopen/fileno undeclared

**Cause:** CPython's `configure.ac` unconditionally adds `-std=c11` when GCC is detected, which disables POSIX features in Newlib.
**Analysis:**
- `configure.ac` line 2389: `CFLAGS_NODIST="$CFLAGS_NODIST -std=c11"` is executed whenever `$GCC` is "yes".
- Newlib's `sys/features.h` respects `-std=c11` (strict ISO C11 mode) by disabling default POSIX visibility macros (`__POSIX_VISIBLE`).
- Although `Makefile.nanvix` passes `-D__POSIX_VISIBLE=200809` and `-std=gnu11`, the `-std=c11` flag from `CFLAGS_NODIST` appears *later* in the compiler command line (via `PY_STDMODULE_CFLAGS`), overriding the earlier flags.
- This causes `fdopen`, `fileno`, and other POSIX-specific functions to be hidden, causing compilation errors.

**Fix:** Patch the generated `Makefile` immediately after `configure` runs to replace `-std=c11` with `-std=gnu11`.
